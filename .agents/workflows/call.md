# /call — 深度记忆整合协议

当用户输入 `/call` + 项目路径时，执行全方位深度记忆同步。

> **与 `/end` 的区别**：`/end` 是对话结束时的快速归档，`/call` 是对话中的**深度整合** —— 不仅更新 Focus，还要触达神经网络的每一个节点。

// turbo-all

## 触发格式

```
/call
/path/to/project
```

## 步骤

### Phase 1: 信息采集（读取全部相关上下文）

1. 读取当前焦点
```
view_file /path/to/记忆系统/10_当前焦点_Focus.md
```

2. 读取中期待办
```
view_file /path/to/记忆系统/11_待办事项_Backlog.md
```

3. 读取项目开发规则
```
view_file /path/to/记忆系统/07_项目开发规则_DevRules.md
```

4. 根据项目路径，读取对应的项目知识卡：
   - `/path/to/project-a` → `view_file 20_Projects/项目A.md`
   - 如果项目涉及领域知识 → 同时读取 `30_Domains/` 对应文件

5. 回顾本次对话的全部上下文（AI 平台原生记忆 + 当前对话历史），提炼：
   - 本次完成了哪些工作
   - 有哪些架构决策或技术变更
   - 有哪些新规则/约定产生
   - 有哪些 Bug 修复或功能上线
   - 有哪些待办产生但还没记录

### Phase 2: 全神经网络写入（逐个节点更新）

按以下检查清单，**逐一**检查并更新每个文件。每个文件都要问："本次对话有没有产生需要写入这个文件的信息？"

| # | 目标文件 | 检查内容 | 写入动作 |
|:--|:---------|:---------|:---------|
| 1 | `10_Focus.md` | 任务完成了？新任务产生了？推理状态变了？ | 标记 `[x]` / 新增条目 / 更新推理状态 |
| 2 | `11_Backlog.md` | 有新的中期待办？已有待办完成了？ | 新增条目(附项目路径) / 标记 `[x]` |
| 3 | `20_Projects/[项目].md` | **里程碑完成？架构决策变更？技术栈变化？** | 更新里程碑表 / 追加架构决策 |
| 4 | `30_Domains/[领域].md` | 有新的领域知识固化？规则变更？ | 压缩追加 |
| 5 | `07_DevRules.md` | 产生了新的编码约定？新项目的配置？ | 追加规则段落 |
| 6 | `秘钥文档/` | 新增了密钥？配置了新的环境变量？ | 更新密钥文件 + 总控台矩阵 |

### Phase 3: 汇报

向用户汇报整合结果：
- 📊 本次对话涉及的项目和工作总结
- ✅ 哪些文件被更新了（逐一列出）
- ⚠️ 哪些文件检查后无需更新（说明原因）
- ❌ 如果有文件 **被跳过了**，必须解释为什么

> **铁则**：`/call` 的汇报中，Phase 2 的每一行都必须有明确的"已更新"或"无需更新"状态。**不允许沉默跳过任何文件。**
